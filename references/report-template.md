# 输出契约（report-template）

> Phase 4 必读。最终产出 `04-research-report.md`。
> 模块按 depth 档位裁剪：快扫 = 模块 1 + 简版 2、3；标准 = 模块 1–10；深度 = 全部 + 双版本解读。
> 「不适用」的模块须标注原因，不得静默删除。

## 模块清单

| # | 模块 | 要求 |
|---|---|---|
| 1 | 一句话结论（TL;DR） | 30 秒可理解；含信心度；深度档须给大白话+专业双版 |
| 2 | 分层领域地图 | 矩阵生成痕迹可见：节点、P0/P1/P2 分区、跨界节点 |
| 3 | 共识 / 前沿 / 争议三分类表 | 每条带【L 级 + as-of】 |
| 4 | 底层机制（WHY） | 因果链解释，禁止罗列 WHAT |
| 5 | 最佳实践清单（HOW） | **仅限 P0 区**；每条带证据 + 适用边界 + 「被谁采用」 |
| 6 | 反方观点与风险 | 至少一条实质性质疑或失败案例；矛盾仲裁结果 |
| 7 | 行动建议 | 分「现在可做 / 需验证后做 / 暂不碰」（purpose=认知时可写「纯认知目的」） |
| 8 | 可证伪条款 | 每条核心判断：什么证据出现会推翻它 |
| 9 | 参考来源 | 全部可回溯（URL/文献/路径），标注 L 级与 as-of |
| 10 | 未解问题 + 研究过程说明 | 含信源降级/缺口登记（降级标注格式见 tool-adapters.md） |

## 填写规则

- 结论先写状态（共识/前沿/争议），再写内容；状态为「争议」时必须写明双方立场
- 结论表的每一行都必须能在「参考来源」中找到对应条目
- D 级/未验证内容只允许出现在「未解问题」，不允许出现在结论表
- 数据型领域须在模块 3 或单独附录中给出原始层（L3 及以上）数据，不得只引用二手数字
