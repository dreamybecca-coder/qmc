# 工具适配层（tool-adapters）

> 本协议的主体与工具无关。本文件把协议中的「逻辑信源角色」映射到当前环境的实际工具。
> 换 Agent / 换环境时，只改本文件，SKILL.md 与其他参考文件不动。
> 原则：**角色不变，工具可换；工具缺失，沿降级链走并在产出中标注缺口。**

## 逻辑角色 → 工具映射

| 逻辑角色 | Kimi Work 环境（当前） | 通用降级链 |
|---|---|---|
| 广谱网页搜索 | WebSearch | 任意搜索引擎 API → 直接 FetchURL 已知权威站点 |
| 网页正文读取 | FetchURL / in-app-browser / kimi-webbridge | 直接 HTTP 抓取 → 标注「仅摘要可用」 |
| 学术论文搜索 | scholar 插件（Google Scholar） | arXiv/bioRxiv/SSRN/PubMed 直接检索 → 广谱搜索 + `site:` 限定 |
| 金融数据（A股/港股） | iFinD 或 Wind 插件 | 交易所官方披露 → 财经数据网站 → 标注缺口 |
| 金融数据（美股/ADR） | SEC EDGAR 插件（一手 filing）→ yahoo_finance | 公司 IR 页面 → 财经数据网站 |
| 宏观经济数据 | imf / world_bank_open_data / igo_open_data 插件 | 各机构官网 API |
| 企业/法律信息（中国） | tianyancha / yuandian_law 插件 | 官方公示系统网站 |
| 原始数据获取（链上、临床试验等） | 对应官方浏览器/注册库直接 FetchURL | 官方公开 API → 标注缺口 |
| 知识库归档 | obsidian / obsidian-knowledge-manager skill | 写入本地 Markdown 目录 → 仅在报告中给全文 |
| 定时复核（Phase 5） | automation skill（定时任务） | 在 05-followups.md 中写明复核清单，提示用户手动触发 |
| 文章级深挖（子流程） | deep-dive skill | 按本协议 Phase 2–3 对单源执行精简版 |

## 使用规则

1. **先查后声明**：使用任何工具前，确认它在当前环境真实存在且可用；不存在立即走降级链，
   不假装调用、不凭记忆补数据
2. **专业数据插件优先**：金融/学术/企业数据的 factual claims 优先用专业插件而非广谱搜索；
   插件报错（鉴权/超时/无权限）视为「此路未通」，走降级链并标注，不得当作「无数据」
3. **交叉核验**：同一关键数据尽量用两个不同角色验证（如插件数据 + 官方披露）
4. **引用纪律**：每条引用必须是本回合工具真实返回的来源；URL 原样保留；本地文件引用给绝对路径
5. **新增工具**：环境新增插件时，在本文件表格中追加映射行，无需改动协议主体

## 降级标注格式

在研究过程说明中统一使用：

```
[降级] 逻辑角色：学术论文搜索 | 首选工具不可用（原因）| 实际使用：arXiv 直接检索 | 影响：可能遗漏付费期刊论文
```
