# QMC 研究协议（QMC Research Protocol）

**QMC = Question → Map → Cognition（命题 → 地图 → 认知）**

> 把任何陌生领域的研究命题，走完一条可审计的研究流水线，
> 交付一套完整的、经校准的、可操作的领域认知——
> 其中每个断言都带着证据等级、可证伪条款和复核日期。
>
> **它交付的不是答案，是一套被审判过的认知。**

---

## 为什么需要 QMC

面对陌生领域，AI 最大的风险不是找不到信息，而是：

- 把**叙事**当共识（「Bittensor 季度收入 $43M」——源头单一、无审计，被媒体循环引用成"事实"）
- 把**单源**当事实（x402 官方自报 165M 笔交易 vs 第三方链上分析的真实日量 ~$28K）
- **不知道自己不知道**（媒体驱动的罗列式调研，会漏掉媒体没覆盖的整个流派）

QMC 把「AI 随口给的像样答案」变成「一条可审计的研究流水线」。

## 与 QBS 的关系

QMC 的思想起点是 [QBS](https://github.com/LearnPrompt/qbs)（Question → Book → Skill），并对它做了维度升级：

| | QBS | QMC |
|---|---|---|
| Q | 卡住的操作问题（How：这事怎么做） | 研究命题（What/Whether：什么是真的） |
| 中间 | **B**ook——答案在一本对的书里 | **M**ap——地图驱动研究；书只是信源五图层中 L1 的一种 |
| 产出 | **S**kill——可复用的操作流程 | **C**ognition——完整的领域认知；skill 只是认知沉淀的可选副产品 |

一句话：**QBS 把问题变成技能（怎么做事），QMC 把命题变成认知（什么是真的、该怎么用）。**

Research 不在缩写里，因为 QMC 就是 Research 的解剖学——六个阶段没有一个是 Research，因为六个全都是。

## 立体结构

### Q · 命题（四层规格化）

| 层 | 动作 | 内容 |
|---|---|---|
| 定性 | 目标三分法 | 认知（搞懂）/ 决策（要不要做）/ 学术（建体系） |
| 分型 | 知识类型 | S 稳定方法论（半衰期>5年）/ F 前沿动态（<2年）/ X 交叉实践（知识散落在案例中） |
| 分层 | 深度档位 | 快扫（值不值得研究）/ 标准 / 深度（重大决策） |
| 定界 | 作用域 | 单一领域 / 交叉领域取交集 A∩B 或并集 (A∪B)∩C（C=真实需求圈） |

### M · 地图（研究的操作界面——全部流程都是对地图的操作）

| 操作 | 做什么 | 防什么 |
|---|---|---|
| 矩阵生成 | 能力原子 × 需求原子做笛卡尔积，三问过滤，跨界巨头强制入图，盲区检查 | 不知道自己不知道 |
| 按图取证 | 信源五图层（L1 可验证一手 → L5 媒体转述）锚定到节点；L4/L5 默认只作线索 | 叙事冒充证据 |
| 逐格审判 | 反向搜索、矛盾仲裁、利益相关降权、流传数字溯源 | 假共识、注水数据 |
| 因果连线 | 机制解释（WHY）优先于事实罗列（WHAT）；认知资产入库 + 复核期 | 盘点式研究报告 |

### C · 认知（最终交付物的解剖）

1. **领域地图本体**：节点 + 关系 + 边界（含 P0/P1/P2 优先级分区）
2. **状态标注**：每个节点是 共识 / 前沿 / 争议 / 未知
3. **断言裁决**：每个结论带【证据等级 + 出处 + as-of 时效 + 可证伪条款 + 复核期】
4. **行动分层 + 开放问题**：现在可做 / 需验证后做 / 暂不碰；下次复核什么

## 流水线：六阶段，每阶段有 Gate（不通过不得进入下一阶段）

```
Phase 0 定题与路由 → Phase 1 建图（结构生成法）→ Phase 2 取证（信噪比闸门）
→ Phase 3 验证（共识/前沿/争议三分类）→ Phase 4 综合与产出 → Phase 5 沉淀与迭代
```

执行宪法 10 条（不可违反）：先定题再研究 / 先制图再取证 / 禁止单源结论 / 禁止硬编 /
双标签随行 / 时效强制 / 流传数字溯源 / 项目方降权 / 优雅降级 / 产出落盘。

质量红线 11 条（违反任意一条即不得交付）：含「地图靠记忆罗列而非矩阵生成」
「在 P1/P2 区认定最佳实践」「数据无 as-of 日期」等。

详见 [SKILL.md](SKILL.md)。

## 实战验证

三类知识路由全部经过真实试跑（含零上下文新实例的回归测试）：

| 路由 | 试跑主题 | 抓到的「假共识」 |
|---|---|---|
| X 交叉实践（两轮，含零记忆重跑收敛验证） | 区块链 × AI 最佳实践 | $43M 收入神话（无审计源头）；x402 交易量注水 |
| F 主 + S 辅 学术型 | 冥想 × 记忆 × 睡眠 | 「冥想增大海马」流行叙事在 n=218 RCT 中复现失败 |
| S 主 方法论（读书子协议实战） | 缠论（精读 10 课原文 + 真实数据试跑） | 「必然赢利」承诺零可审计证据；可执行性呈梯度衰减 |

## 文件结构

```
qmc/
├── SKILL.md                      # 协议本体：宪法 + 输入参数 + Phase 0–5 + 质量红线
├── README.md                     # 本文件
└── references/
    ├── source-playbook.md        # S/F/X 三信源栈 + 领域陷阱表 + 读书子协议（附录 A）
    ├── report-template.md        # 输出契约 10 模块（按档位裁剪）
    └── tool-adapters.md          # 逻辑信源角色 → 实际工具映射 + 降级链
```

跨 Agent 移植：协议主体与工具无关；换环境只需适配 `references/tool-adapters.md`。

## 安装

支持 skills 标准的 Agent（Kimi Code / Claude Code / Codex 等）：

```bash
npx skills@latest add dreamybecca-coder/qmc --skill qmc
```

或手动：把 `qmc/` 目录复制到 `~/.config/agents/skills/`（或你的 Agent 的 skills 目录），
也可以直接把 SKILL.md 内容作为 system prompt 使用。

## 使用

```
使用 QMC。我想研究 [某陌生领域/主题]，目的是 [认知/决策/学术]，深度 [快扫/标准/深度]。
```
